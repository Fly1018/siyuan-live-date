# 动态日期（siyuan-live-date）

**让指定文档里的日期「活着」** —— 今天打开显示今天，明天打开显示明天；**只改显示，不改数据**，笔记里存的仍然是你写的标记。

兼容思源笔记 v3.0.0+ · 包名 `siyuan-live-date` · [仓库](https://github.com/Fly1018/siyuan-live-date)

## 核心功能

- **行内标记**：`@today` 显示为当天日期（`2026-09-26`），`@now` 显示为当前时间（`2026-09-26 12:30:45`）
- **块属性**：给块加 `custom-live-date`，该块的日期按属性值指定的格式刷新
- **两种生效范围**：按文档加属性（逐篇控制），或按笔记白名单（整本生效）
- **只改显示，不改数据**：替换的是页面上的文本节点，块数据里的 `@today` 原封不动
- **保留行内格式**：`**【@today】**` 渲染成 `【2026-09-26】`，加粗和括号都不丢
- **自动跳过不该动的地方**：代码块、公式块、HTML 块以及一切不可编辑区域

## 适用场景

- 日记 / 周记模板里的「今天」：每天新建的日记自动显示当天日期
- 只有「当前日期」「当前时间」的看板、清单、打卡页
- 只想在**某几篇**文档生效（用文档属性），或**整本笔记本**都生效（用白名单）
- 需要按自定义格式显示日期，例如 `2026年09月26日` 或 `2026-09-26 12:30`

## 安装与启用

**方式一：集市安装（推荐）**

1. 思源 → <kbd>设置</kbd> → <kbd>集市</kbd> → <kbd>插件</kbd>，搜索「动态日期」
2. 点安装
3. 到 <kbd>设置</kbd> → <kbd>集市</kbd> → <kbd>已下载</kbd>，把「动态日期」的开关打开

**方式二：手动安装**

1. 从 [最新 Release](https://github.com/Fly1018/siyuan-live-date/releases/latest) 下载 `package.zip`
2. <kbd>设置</kbd> → <kbd>集市</kbd> → <kbd>已下载</kbd> → 从 `package.zip` 安装
3. 同样在「已下载」里启用

**指定生效范围**（二选一，也可以同时用）：

- **单篇文档**：在该**文档块**上添加属性 `custom-live-date`，值留空或写 `on`
- **整个笔记本**：<kbd>设置</kbd> → <kbd>集市</kbd> → <kbd>已下载</kbd> → 动态日期（齿轮）→ 在「生效笔记本」里填笔记本 ID（一行一个），或点下面的「**加入当前文档所在笔记本**」按钮自动填入

打开文档时渲染即生效，不需要额外操作。

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 思源笔记版本 | **v3.0.0 或更高**（插件清单 `minAppVersion: 3.0.0`） |
| 后端 / 前端 | 清单声明兼容全部（`backends: all`、`frontends: all`） |
| 额外依赖 | 无。插件是单个 `index.js`，由思源直接加载，不需要 Node/Python 等运行时 |
| 网络 | 不需要联网，只调用本地内核 API |

> 导出 PDF / 图片、安全模式、连接远程内核时插件本身不会加载，因此这些场景下日期不会变化。

## 快速上手

1. 打开一篇文档，在**文档块**上添加属性 `custom-live-date`，值留空或写 `on`

2. 在正文里输入：

   ```
   今天：@today
   ```

3. 文档加载完成后显示为 `今天：2026-09-26`

4. 再试试另外两种写法：

   - `@now` → `2026-09-26 12:30:45`
   - 输入斜杠命令 `/dqr`（或 `/live`）→ 插入 `【@today】`

5. 想让某个块整块都显示日期：给这个块加属性 `custom-live-date`，值写格式，例如 `yyyy年MM月dd日`

没看到变化时，先重开一次该文档（生效判断有缓存，见「已知边界」）。

## 配置项

<kbd>设置</kbd> → <kbd>集市</kbd> → <kbd>已下载</kbd> → 动态日期（齿轮图标）；
也可以搜索命令「动态日期：打开设置」。

| 设置项 | 含义 | 默认值 |
| --- | --- | --- |
| **生效笔记本** | 笔记本白名单。这些笔记本下的文档**不用加属性**也会自动刷新日期。一行一个笔记本 ID，也接受逗号或空格分隔；留空表示只靠文档属性生效 | **空** |
| **调试日志** | 把每次实际替换写进 `data/storage/petal/siyuan-live-date/debug.json`（最多保留 30 条，每 5 秒合并写一次），排障用 | **关** |
| **快捷操作** | 「加入当前文档所在笔记本」按钮：把当前文档所在笔记本 ID 追加进上面的列表 | — |

### 属性与占位符

**文档块属性 `custom-live-date`** —— 控制这篇文档是否生效：值**不是** `off` / `false` / `0`（不区分大小写）即视为开启；属性不存在、或值为上述三者、或删掉属性，则不生效。

**普通块属性 `custom-live-date`** —— 控制这个块显示成什么日期：该属性所在块**第一个文本节点**会被整段替换成按格式生成的当天日期。值留空或写 `on` 时用默认格式 `yyyy-MM-dd`。

支持的格式占位符：

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `yyyy` | 四位年份 | `2026` |
| `yy` | 两位年份 | `26` |
| `MM` | 两位月份 | `09` |
| `dd` | 两位日期 | `26` |
| `HH` | 两位小时（24 小时制） | `12` |
| `mm` | 两位分钟 | `30` |
| `ss` | 两位秒 | `45` |
| `ECN` | 星期几，固定输出中文「日一二三四五六」 | `六` |

只要属性值里含**任意一个**占位符，就按它格式化；一个都没有的话整段用默认的 `yyyy-MM-dd`。

**行内标记 `@today` / `@now`** —— 这两种格式是**固定的，不可自定义**：`@today` 为 `yyyy-MM-dd`，`@now` 为 `yyyy-MM-dd HH:mm:ss`。

## 进阶用法

### 自定义日期格式

在块属性 `custom-live-date` 的值里拼占位符即可：

| 属性值 | 显示结果 |
| --- | --- |
| （留空）或 `on` | `2026-09-26` |
| `yyyy年MM月dd日` | `2026年09月26日` |
| `yyyy-MM-dd HH:mm` | `2026-09-26 12:30` |
| `yyyy/MM/dd（ECN）` | `2026/09/26（六）` |

### 斜杠命令

在编辑器里输入 `/dqr` 或 `/live`，会出现「动态日期 `@today`」这一项，回车即插入 `【@today】`。

### 临时停用

- **停用某篇文档**：删掉文档块上的 `custom-live-date` 属性，或把值改成 `off` / `false`，然后重开一次该文档
- **停用某个笔记本**：在设置里删掉对应 ID 并点确定（会立即清缓存生效，不用重载插件）

## 已知边界

1. **只改显示，不改数据**：笔记里存的仍然是 `@today`。但如果你在那一行**输入并保存**，思源会把当前显示的日期当成内容存下来，标记就没了，需要重新打一次
2. **块属性模式会整段替换第一个文本节点**：如果块里除了日期还有别的文字（例如 `今天 2026-01-01`），这些文字会被一起覆盖。所以这个属性只适合**整块内容就是日期**的块
3. **代码块、公式块、HTML 块里的标记不会被替换**，避免污染数据
4. 导出 PDF / 图片、安全模式、连接远程内核时不生效（插件本身不加载）
5. 渲染时机是「文档加载完成」以及「文档有改动后 0.6 秒」，所以刚打开的一瞬间可能仍显示 `@today`
6. 判断文档是否生效需要一次 `/api/attr/getBlockAttrs` 调用，结果会缓存：**未生效 3 秒 / 已生效 60 秒**

## 常见问题

**日期没有变化**

1. 确认文档在生效范围内：文档块上有 `custom-live-date`（值不是 `off` / `false` / `0`），或者它所在笔记本在设置的白名单里
2. 重开一次该文档，或等缓存过期（未生效 3 秒 / 已生效 60 秒）
3. 打开**调试日志**，看 `data/storage/petal/siyuan-live-date/debug.json`：只有 `onload` 没有 `render`，说明这篇文档不在生效范围，或者没找到标记
4. 确认那一行不在代码块 / 公式块 / HTML 块里

**调试日志里出现 `gate-error`**

读取文档属性失败，此时插件会「放行」照常渲染，属于容错行为，不影响使用。若频繁出现，检查思源版本是否正常、或换个文档再试。

**为什么刚打开的一瞬间还显示 `@today`**

渲染发生在文档加载完成之后，而且文档改动后有 0.6 秒的合并延迟，所以会有一瞬间显示原始标记，属正常现象。

**编辑过那一行之后标记消失了**

见「已知边界」第 2 条：在那一行输入并保存时，思源会把当前显示的日期当作内容存下来，重新打一次 `@today` 即可。想避免这种情况，就别在被替换的那一行里直接编辑。

**想只在某几篇文档生效 / 想整本笔记本都生效**

- 只在某几篇 → 用**文档属性**（可随文档一起同步、导出，推荐）
- 整本都生效 → 用**笔记本白名单**（只对当前这台设备有效，因为它记的是笔记本 ID）

**怎么知道笔记本 ID？**

不用手抄：在设置里点「**加入当前文档所在笔记本**」，它会自动把当前文档所在笔记本的 ID 填进列表。

## 开发与发版

**仓库根目录就是插件本体**：思源直接加载 `index.js`（CommonJS，`require("siyuan")`），不需要编译或构建，改完保存即可生效。完整的版本记录见 `CHANGELOG.md`。

```bash
python3 scripts/pack.py          # 校验并打出 package.zip
python3 scripts/pack.py --check  # 只校验，不生成
```

发版步骤：

1. 改 `plugin.json` 里的 `version`，并在 `CHANGELOG.md` 补一条；
2. 提交，打一个与版本号一致的 tag 并推送：

   ```bash
   git tag v0.6.1 && git push origin v0.6.1
   ```

3. GitHub Actions 会校验 tag 与版本号一致 → 打包 `package.zip` → 发布 Release。

集市索引会在 1–3 小时内自动拉到新版本，**不需要再提 PR**。
